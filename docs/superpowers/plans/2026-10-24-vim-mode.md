# Vim Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the note editor an optional vim mode with real vim defaults, plus the owner's own keymaps written in a Lua subset.

**Architecture:** The `<textarea>` in `NotePane` becomes a CodeMirror 6 view wrapped by `CodeEditor`, which exposes an `EditorHandle` (body/focus/selection/replaceRange) so nothing outside `web/src/editor/` imports `@codemirror/*`. The owner's config text lives in the encrypted `AccountSettings` blob, is compiled by a hand-written Lua-subset parser into a `VimConfig`, and is applied to `@replit/codemirror-vim`'s module-global `Vim` object. No Lua interpreter and no evaluation of user text.

**Tech Stack:** TypeScript, React 18, Vitest + jsdom, CodeMirror 6, `@replit/codemirror-vim` 6.4.0.

**Spec:** `docs/superpowers/specs/2026-10-24-vim-mode-design.md`

## Global Constraints

- Vim mode is **off by default**, for new and existing accounts.
- No `eval`, `new Function`, `loadstring` or any execution of config text. It is parsed, never run.
- Nothing outside `web/src/editor/` may import from `@codemirror/*` or `@replit/codemirror-vim`.
- `@replit/codemirror-vim` is loaded by `await import()` only when vim mode is on. CM6 core is a static import.
- The openboard entries must stay free of CodeMirror, crypto, store and session code: `npm run build -w web && npm run check:openboard -w web` must pass.
- Supported option allowlist, exactly: `number`, `relativenumber`, `wrap`, `tabstop`, `expandtab`, `ignorecase`, `smartcase`, `scrolloff`.
- Supported keymap modes, exactly: `n`, `i`, `v`.
- `vim.keymap.set` defaults to non-remapping (`Vim.noremap`); `remap = true` means `Vim.map`.
- A config with any error applies **no** custom keymaps and no options; vim defaults still work.

## Review Focus

1. **CRLF bodies.** A `<textarea>` silently normalises `\r\n` to `\n`; CM6 stores what it is handed. A note pasted from Windows would start saving `\r\n` and its bytes would change on open. `CodeEditor` must normalise incoming `value` to `\n`. Test in Task 5.
2. **A huge config.** The owner pastes a 2 MB `init.lua`. The compiler must refuse past a cap rather than walk it. Test in Task 3.
3. **A malformed `vim` value in the settings blob.** Hand-edited or written by a future version: `isAccountSettings` must reject it so the blob counts as unreadable, instead of reaching the compiler as a non-string. Test in Task 1.
4. **Turning vim off.** `Vim.map` is module-global, so disabling vim must `mapclear` — otherwise the keymaps stay live in a reconfigured editor. Test in Task 4.
5. **A duplicate `lhs`.** Two lines binding the same key in the same mode: the later wins, applied in file order, with no error. Test in Task 2.
